# GitHub Pages 포트폴리오 구축·게시 계획

## 목표

`wnwjdals7498.github.io` 사용자 사이트에 정적 포트폴리오를 게시한다. 프로젝트별 배경·개인 역할·현재 상태·검증 근거를 구분하고, 실제 회사 업무와 개인 재현 구현을 명확히 분리한다.

## 구현 선택

- 외부 빌드 도구나 원격 스크립트 없이 HTML·CSS·JavaScript 정적 파일로 구성한다.
- `main` 브랜치의 저장소 루트를 Pages 게시 소스로 사용한다. 루트 `index.html`이 진입점이며 `.nojekyll`로 Jekyll 처리를 비활성화한다.
- 첫 화면은 [승인한 목업](ui/mockup.html)의 시각 방향을 따르고, 프로젝트별 상세 HTML을 별도로 둔다.
- 상태 필터는 계획·진행 중·구현 완료·검증 완료를 구분한다. 현재 확인한 네 프로젝트는 모두 계획 단계다.
- 회사명·서비스명·제품명, 고객 정보, 내부 주소, 원본 자료를 게시하지 않는다. 공개 연락처는 GitHub 프로필만 둔다.

## 작업 순서

1. 첫 화면, 공통 스타일, 상태 필터, 프로젝트 상세 페이지와 404 페이지를 작성한다. **완료.**
2. HTML 구조·내부 링크·JavaScript 문법을 점검한다. **완료.**
3. 공개 콘텐츠에 내부 주소·연락처와 확인되지 않은 경력·성과 표현이 없는지 확인한다. **완료.**
4. GitHub에 변경을 반영하고 사용자 사이트의 루트 `index.html`이 게시되는지 확인한다. **완료.**
5. 공개 URL에서 첫 화면·네 상세 페이지·상태 필터·모바일 폭·404와 복귀 링크를 확인한다. **완료.**

## 게시 후 갱신 규칙

- 프로젝트가 착수되면 실제 작업 근거를 확인하고 진행 중으로 바꾼다.
- 구현 완료와 검증 완료는 각각 코드와 재현 가능한 시험 결과가 있을 때만 표시한다.
- 재직 기간·직무·팀 변경 시점은 비공개 기록과 대조한 뒤 입력한다.
- 프로젝트 상세 페이지에는 시험 환경과 한계를 함께 적는다. 개인 재현 결과를 회사 운영 성과로 쓰지 않는다.

## 확인 기준

- `https://wnwjdals7498.github.io/`에서 첫 화면과 네 상세 페이지가 열린다.
- 각 프로젝트의 표시 상태가 저장소의 실제 구현·검증 상태와 일치한다.
- GitHub 프로필 외 연락처와 회사 원본·비공개 자료가 게시되지 않는다.
