# 포트폴리오 사이트 구축 계획

## 목표와 경계

- 프로젝트 구현 전에 GitHub Pages 사이트를 개설한다.
- 계획 단계와 진행 중인 프로젝트도 표시하되, 미실행 작업을 완료 결과로 표현하지 않는다.
- 실제 회사 업무와 개인 재현 구현을 명확히 구분한다.
- 외부에 공개할 자료는 설명, 공개 코드 링크, 민감정보를 제거한 검증 결과로 제한한다.

## 단계

1. 사이트 구조와 프로젝트 상태 표시 방식을 정한다. 첫 게시 시 모든 프로젝트의 실제 상태를 확인한다.
2. 프로젝트별 요약 페이지를 만든다. 배경·역할·구현 범위·검증 결과를 구분하고, 결과가 없으면 계획으로 표시한다.
3. 회사·서비스·제품명을 익명화한다. 재직 기간·직무·팀 변경 시점은 이력서와 비공개 기록을 대조한 뒤 반영한다.
4. 공개 저장소와 연결한다. 구현·검증 상태가 바뀌면 사이트와 README를 함께 갱신한다.
5. 공개 전 민감정보와 성과 표현을 검토한다. 개인 재현 결과를 회사 운영 시스템의 성과로 표현하지 않는다.

## 확인 기준

- GitHub Pages에서 사이트가 열리고, 계획·진행·구현·검증 상태가 실제 작업과 일치한다.
- GitHub 프로필 외 연락처와 비공개 원문이 게시되지 않는다.
- 회사 업무와 개인 구현의 출처가 페이지마다 구별된다.

## 아직 정하지 않은 것

디자인, 사이트 구현 기술, 상세 페이지 구성과 게시 일정의 세부 날짜는 착수 시 결정한다.
