# 포트폴리오 UI 가이드 · 시안

> [HTML 목업](mockup.html)은 디자인 검토용이다. 사이트 구현·배포·검증은 아직 하지 않았다.

## 핵심 메시지

시스템 개발과 플랫폼 운영 경험을 바탕으로 개인 환경에서 다시 설계한 프로젝트를 보여준다. 화면은 **배경 → 맡은 역할 → 구현 상태 → 검증 근거** 순서로 읽히게 한다.

## 페이지 구조

1. **첫 화면:** GitHub 사용자명 `wnwjdals7498`, 작업 분야, 포트폴리오의 목적. 연락처는 GitHub 프로필 링크만 둔다.
2. **프로젝트:** 프로젝트별 계획·진행·구현·검증 상태, 범위, 사용 기술, 공개 저장소 링크. 통합된 PHP·Linux 프로젝트는 한 카드로 보여준다.
3. **업무 경험과 개인 재현:** 출처를 나눠 설명한다. 재직 기간·직무·팀 변경 시점은 기록 대조 후 입력한다.
4. **검증 방법:** 로그와 재현 절차를 공개할 때 민감정보를 제거하고, 검증하지 않은 결과는 계획으로 표시한다.

## 시각 방향

- 짙은 남색의 도입부와 밝은 콘텐츠 영역을 사용한다. 기술 포트폴리오의 밀도를 유지하되 긴 문장을 줄인다.
- 제목은 크게, 본문은 짧게. 카드마다 한 가지 핵심 메시지를 둔다.
- 상태 배지는 텍스트와 색을 함께 사용한다: 계획(회색), 진행 중(파랑), 구현 완료(보라), 검증 완료(청록).
- 데스크톱에서는 주요 프로젝트를 넓게, 나머지를 두 열 카드로 표시한다. 모바일에서는 한 열로 정렬한다.
- 외부 폰트·이미지 없이도 열리는 정적 HTML을 기본으로 한다. 실제 사이트의 구현 기술은 Pages 세부 계획에서 결정한다.
- 키보드 포커스, 충분한 명도 대비, 44px 이상 주요 링크 높이와 모바일 탐색을 확인한다.

## 공개 내용 규칙

- 회사·서비스·제품명, 고객 정보, 내부 주소와 원문 자료를 싣지 않는다.
- 실제 회사 업무와 개인 환경에서 새로 만든 구현을 같은 성과로 표현하지 않는다.
- 화면의 `계획` 상태는 README나 구현·검증 근거가 갱신되기 전까지 임의로 올리지 않는다.
- `j-game/drone-simulator`는 현재 로컬 폴더가 확인되지 않아 이 목업의 프로젝트 카드에서 제외했다. 게시 전 다시 확인한다.
- 재직 정보는 확인된 기록을 대조한 다음 공개한다. 목업에 가짜 경력·기간을 넣지 않는다.
